# File Splitter 프로젝트 구성

- `pom.xml`은 Java 17과 Spring Boot 4.2.0 기반의 독립 Maven 모듈을 정의한다. package에서 단일 실행 JAR을 생성하고 소스 JAR을 첨부한다. 모듈 루트의 Markdown은 실행 JAR과 소스 JAR의 `META-INF/docs/file-spliter/`에 포함한다.
- `FileSplitterApplication`은 웹 서버 없이 시작하는 CLI 진입점이다. 첫 인수의 `split` 또는 `analyze`에 따라 해당 서비스를 실행한다.
- `InputFiles`는 분할을 시작하기 전에 입력 경로와 파일명 패턴을 경로 목록으로 해석한다. 패턴은 지정된 폴더의 직접 하위 파일을 파일명 오름차순으로 선택한다.
- `FileSplitter`는 일반 파일과 gzip 압축 파일을 UTF-8로 한 줄씩 읽고, 정규식에서 검출한 키에 대응하는 UTF-8 출력에 기록한다. 입력 목록 전체에서 직전 키와 키별 출력 스트림을 공유한다.
- `FileAnalyzer`는 분할 폴더 바로 아래의 일반 파일을 한 줄씩 검사한다. 매치가 발견되면 검색을 끝내고 그 파일을 결과 폴더에 원래 이름으로 복사한다.
- `FileSplitterTest`는 여러 파일에 걸친 키 전환과 재사용, 일반 파일과 gzip 혼합 입력, 잘못된 gzip 헤더, UTF-8 BOM, 캡처 그룹이 없는 정규식, 매치 없는 입력, 출력 경로 충돌과 안전하지 않은 키를 검증한다.
- `FileAnalyzerTest`는 매치 파일의 전체 바이트 보존, 하위 폴더 건너뛰기, 결과 파일 충돌과 동일한 입출력 디렉터리 거부를 검증한다.
- `InputFilesTest`는 패턴과 개별 경로의 혼합 순서, 파일명 패턴에 일치하는 디렉터리 제외, 빈 매치와 폴더명 와일드카드 거부를 검증한다.

## 분할 정책

- 한 라인에서 첫 번째 정규식 매치를 사용한다. 캡처 그룹이 있으면 그룹 1을, 없으면 매치 전체를 키로 사용한다. 키가 없거나 비어 있는 매치는 오류다.
- 첫 매치 전의 라인은 건너뛴다. 이후 매치되지 않는 라인은 직전 키의 파일에 기록한다. 입력의 줄바꿈은 출력에서 LF로 통일한다.
- 확장자가 대소문자 구분 없이 `.gz`인 입력은 `GZIPInputStream`으로 읽으면서 압축을 해제한다. 압축 해제 중 입출력 오류가 발생하면 작업을 종료하고 열린 출력 스트림을 닫는다.
- 각 키의 출력은 `<키>.txt`다. 기존 파일이나 심볼릭 링크와 충돌하면 실패한다. 출력 스트림은 새 키가 검출될 때 열고 성공과 실패 모두에서 일괄 닫는다. 작업 도중 실패하면 이미 생성한 출력은 남는다.
- 메모리에 전체 입력을 올리지 않는다. 동시에 여는 출력 스트림 수는 검출된 고유 키의 개수에 비례한다.

## 분류 정책

- 분할 폴더의 직접 하위 일반 파일을 UTF-8로 읽고 Java 정규식의 `find()`로 검사한다. 파일 맨 앞의 UTF-8 BOM은 검색에서 건너뛴다.
- 매치가 있는 파일마다 결과 폴더에 원본 바이트를 한 번 복사한다. 하위 폴더와 심볼릭 링크는 건너뛰며, 결과 경로 충돌은 입출력 오류로 처리한다.
- 분할 폴더와 결과 폴더는 서로 달라야 한다. 실패 전까지 복사된 파일은 결과 폴더에 남는다.

## 검증

테스트를 활성화한 Maven verify에서 분할과 분류를 검증한다. 기본 install의 테스트 생략, 실행 JAR의 두 명령, 소스 JAR과 Markdown 포함 여부를 확인한다.
